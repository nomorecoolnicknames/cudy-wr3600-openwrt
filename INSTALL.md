# Установка и обновление — Cudy WR3600 (BCM6764), Linux 6.6 + OpenWrt 24.10

Четыре способа. Первые два ставят прошивку с заводской системы и пишут
**только слот 1** (тома UBI `bootfs1`/`rootfs1`); заводская прошивка остаётся
в слоте 2, загрузчик (`loader`, `u-boot`) и данные платы (`bdinfo`) не
трогаются. Способы 3 и 4 обновляют уже установленную прошивку по схеме A/B
(пишется **другой** слот). UART, TFTP и recovery-режим не нужны нигде.

Нужны два файла из релиза: `bootfs-release.itb` (ядро) и `rootfs.sq`
(система); для способа 4 — `cudy-wr3600-sysupgrade-<версия>.tar`. Суммы — в
`SHA256SUMS`.

## Способ 1 — с компьютера, одной командой (рекомендуется)

Требуется: Python 3.8+, OpenSSH-клиент (`ssh`, `scp`, `ssh-keygen`). Linux,
macOS, Windows 10/11 (встроенный OpenSSH) подходят. Компьютер подключён к
роутеру по проводу или по Wi-Fi, роутер на заводской прошивке, адрес
`192.168.10.1`, пароль администратора от веб-интерфейса известен.

```sh
python3 cudy-install.py --router 192.168.10.1 --password 'ПарольВебИнтерфейса' \
    bootfs-release.itb rootfs.sq
```

Скрипт:

1. входит в веб-интерфейс;
2. включает root-SSH на заводской прошивке. Переключателя SSH у неё нет,
   поэтому используется **инъекция в поле `remote` загружаемого OpenVPN-профиля**
   (метод из гайда для Cudy TR3000, `github.com/AkihaZhang/cudy-tr3000-ssh-root`;
   на 4PDA описано то же): при генерации конфига значение `remote` попадает в
   shell-команду, поэтому `1.2.3.4';<команда>;#` выполняется от root по
   «Save & Apply». Внутри — установка свежего SSH-ключа и подъём dropbear на
   порту 2222.
   Важное отличие от «хука `user_up`», которым это делали раньше: инъекция
   **не требует, чтобы VPN-клиент стока запустился** (тот иногда не стартует
   после перезагрузки, и тогда хук не срабатывает — на этом плата один раз
   осталась недоступной). Проверено: скрипт поднимает SSH на стоке, где SSH
   не было вообще, и дальше ставит прошивку.
3. копирует образы, пишет их в слот 1 через штатный `ubiupdatevol`, сверяет
   контрольные суммы прочитанного;
4. делает слот 1 загрузочным (`bcm_bootstate +1`) и перезагружает.

Для первой пробы можно не делать слот постоянным:

```sh
python3 cudy-install.py --router 192.168.10.1 --password '...' --no-commit \
    bootfs-release.itb rootfs.sq
```

— тогда новая прошивка загрузится **один раз**, а следующая перезагрузка
вернёт заводскую. Понравилось — запустите без `--no-commit` (или из новой
системы: ничего, оно уже записано; достаточно из заводской `bcm_bootstate +1`).

Только включить SSH и посмотреть на заводскую систему изнутри:

```sh
python3 cudy-install.py --router 192.168.10.1 --password '...' --ssh-only
ssh -p 2222 -i ~/.cudy-install/id_ed25519 root@192.168.10.1
```

## Способ 2 — руками по SSH на заводской прошивке

Если root-SSH на заводской прошивке уже есть (порт 2222):

```sh
scp -O -P 2222 -i КЛЮЧ bootfs-release.itb rootfs.sq install-on-router.sh root@192.168.10.1:/tmp/
ssh -p 2222 -i КЛЮЧ root@192.168.10.1 'sh /tmp/install-on-router.sh /tmp/bootfs-release.itb /tmp/rootfs.sq'
```

Переменные: `SLOT=2` (писать во второй слот — только если понимаете зачем),
`COMMIT=no` (загрузить один раз), `REBOOT=no`.

## Способ 2b — совсем вручную, без наших скриптов

То же самое четырьмя штатными командами заводской прошивки. Нужен только
root-SSH на стоке (порт 2222) — его поднимает `cudy-install.py` (способ 1), а
дальше можно ничего нашего не запускать.

Разметка UBI на этом роутере (проверить: `cat /sys/class/ubi/ubi0_3/name` →
`bootfs1`): слот 1 — `bootfs1 = /dev/ubi0_3` (ядро) и `rootfs1 = /dev/ubi0_4`
(система); слот 2 — `bootfs2 = /dev/ubi0_5`, `rootfs2 = /dev/ubi0_6` (там
заводская прошивка, **не трогать**). Загрузчик, `bdinfo` и `uboot*` — отдельные
тома, их тоже не касаемся.

Копируем образы на роутер и заходим по SSH:

```sh
scp -O -P 2222 -i КЛЮЧ bootfs-release.itb rootfs.sq root@192.168.10.1:/tmp/
ssh -p 2222 -i КЛЮЧ root@192.168.10.1
```

Дальше — на самом роутере (заводская прошивка):

```sh
# Заводской том rootfs1 — 184 LEB (23 363 584 Б), наш образ больше, поэтому
# сначала расширяем том до 192 LEB. UBI делает это на месте; свободные
# блоки видно в "ubinfo /dev/ubi0" (строка available).
ubirsvol /dev/ubi0 -n 4 -S 192

# записать оба тома слота 1 штатным ubiupdatevol
ubiupdatevol /dev/ubi0_3 /tmp/bootfs-release.itb    # ядро
ubiupdatevol /dev/ubi0_4 /tmp/rootfs.sq             # система
sync

# по желанию — сверить, что записалось без ошибок (суммы должны совпасть):
head -c "$(wc -c < /tmp/bootfs-release.itb)" /dev/ubi0_3 | sha256sum
sha256sum /tmp/bootfs-release.itb

# сделать слот 1 загрузочным и перезагрузиться
bcm_bootstate +1
reboot
```

Через ~2 минуты — Wi-Fi `CudyWR3600` / `12345678`, роутер на `192.168.10.1`.

Хотите сначала попробовать, не делая слот постоянным (следующая перезагрузка
вернёт заводскую) — вместо `bcm_bootstate +1; reboot`:

```sh
bcm_bootstate +1
echo 1 > /proc/bootstate/reset_reason    # загрузить слот 1 один раз
reboot
```

Понравилось — из уже загруженной новой системы делать ничего не нужно, слот
уже записан; чтобы закрепить его из заводской системы, достаточно
`bcm_bootstate +1`. Обратно на заводскую — `bcm_bootstate +2 && reboot` из
стоковой системы.

## Способ 3 — обновление из уже установленной прошивки

Роутер уже на этой прошивке (в `/etc/cudy-release` есть версия), нужно
поставить новую сборку:

```sh
scp -O bootfs-release.itb rootfs.sq ubiwrite update-from-release.sh root@192.168.10.1:/tmp/
ssh root@192.168.10.1 'sh /tmp/update-from-release.sh /tmp/bootfs-release.itb /tmp/rootfs.sq'
```

`ubiwrite` — статический бинарник из релиза (исходник `tools/ubiwrite.c`); с
версии 2026-09-10.3 он и сам скрипт уже лежат в прошивке (`/usr/bin`), копировать
их не обязательно. Скрипт пишет **другой слот** (работающая система остаётся
откатом), сверяет записанное (sha256 ядра, монтирование нового rootfs),
переключает загрузку на новый слот и перезагружает. Работает в фоне (лог
`/tmp/update-from-release.log`), так что оборванная SSH-сессия обновление не
сорвёт. Если в другом слоте заводская прошивка, скрипт **откажется** её
затирать без `FORCE=1` — тогда вернуться на сток можно будет только через
TFTP-recovery с подписанным заводским образом.

## Способ 0 — из LuCI, с версии 2026-09-12

System → Firmware update (GitHub) → Install: роутер сам берёт последний релиз с
GitHub (`cudy-update` проверяет `.sha256` и `sysupgrade --test`), ставит его в
другой слот с сохранением настроек и перезагружается. Там же — «Return to
factory firmware» (пока заводская прошивка в другом слоте). С компьютера то же:
`python3 cudy-install.py --to-stock` (роутер на нашей прошивке, root/12345678).

## Способ 4 — `sysupgrade` (LuCI или консоль), с версии 2026-09-11

LuCI → System → Backup / Flash Firmware → «Flash new firmware image» →
файл `cudy-wr3600-sysupgrade-<версия>.tar`. Или из консоли:

```sh
scp -O cudy-wr3600-sysupgrade-<версия>.tar root@192.168.10.1:/tmp/
ssh root@192.168.10.1 'sysupgrade -v /tmp/cudy-wr3600-sysupgrade-<версия>.tar'
```

То же A/B, что и в способе 3, но **без защиты заводского слота**: явный
`sysupgrade` пишет другой слот, что бы там ни было. То есть **первый
`sysupgrade` затирает заводскую прошивку**; после него в двух слотах живут две
версии этой прошивки, и откат на сток — только TFTP-recovery. Настройки
переживают обновление (они в своём томе `cudy66_data`); «Keep settings» снят /
`sysupgrade -n` — том стирается, роутер загружается как из коробки.

## После установки

- Wi-Fi: `CudyWR3600`, пароль `12345678`; адрес роутера `192.168.10.1`
  (LuCI — `http://192.168.10.1`, SSH — `root`, пароль `12345678`).
- **Кабель провайдера — в WAN-порт**, устройства — в LAN1–4 или по Wi-Fi
  (с версии 2026-09-10.4; раньше WAN-порт не линковал).
- Смените оба пароля (`passwd`; Wi-Fi — в LuCI → Network → Wireless, там же
  канал и ширина). С версии 2026-09-11 настройки хранятся в томе `cudy66_data` и
  переживают перезагрузку; сброс — LuCI «Perform reset» или `firstboot -y`.
  Со стороны WAN вход на SSH/LuCI по умолчанию открыт только из частных
  адресов (`wan_admin` в `/etc/config/wifi66`).

## Откат на заводскую прошивку

Заводская прошивка осталась в слоте 2 — пока вы не сделали `sysupgrade`
(способ 4) или `FORCE=1` в способе 3: они пишут именно этот слот. Из любой
живой системы на плате:

```sh
bcm_bootstate +2 && reboot          # на заводской прошивке
```

Из нашей системы утилиты `bcm_bootstate` нет — используйте способ ниже.

Если новая прошивка не загрузилась: подождите. Если userspace не перевзвёл
сторожевой таймер за 300 с после старта ядра, плата сама сбрасывается и
загрузчик берёт другой слот.

Recovery по TFTP (Reset ≥ 10 с при включении, `192.168.0.250`) принимает
только **подписанный заводской** образ; нашу сборку он отвергнет, ничего не
записав. Это безопасно, но бесполезно — держите заводской `recovery`-образ с
сайта Cudy на случай, если понадобится вернуть завод целиком.
